## 2024-05-24 - [CRITICAL] GROQ Query Injection and Undefined Parameters
**Vulnerability:** In `src/data/page.js`, user-provided `id` values were being unsafely interpolated into a Sanity GROQ query using string templates: ``*[_type == "page" && _id == "${id}"]``. Additionally, falsy/undefined input for the parameter could cause Sanity client failures during static generation and server-side rendering, breaking the build.
**Learning:** String interpolation for variables within GROQ queries permits injection attacks similar to SQL injection, letting users manipulate the dataset queried or fetched. We also learned that Sanity queries starting with `*` return arrays by default, and handling an undefined parameter by returning null changes the expected type, so we must return an empty array `[]` instead.
**Prevention:** Always use parameterized GROQ queries (e.g. `$id`) and pass parameters as an object to `client.fetch()`. Check parameters for truthiness before querying; if missing, return a default value that matches the expected GROQ return type (like `[]` instead of `null` for array responses).
