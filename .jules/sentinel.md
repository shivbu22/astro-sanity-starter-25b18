## 2024-05-24 - [GROQ Injection in Sanity Client]
**Vulnerability:** The application was vulnerable to GROQ injection because it used string interpolation for dynamic queries like `*[_type == "page" && _id == "${id}"]`. If an attacker managed to control the `id` value, they could have manipulated the GROQ query structure, potentially accessing unauthorized data or modifying the query intent.
**Learning:** Sanity GROQ queries can be injected into just like SQL queries if string interpolation is used for parameter values. The build process can also crash if `client.fetch()` encounters authorization errors or null parameters (especially during static site generation) unless the calls are wrapped in `try/catch` with safe fallback returns.
**Prevention:** Always use parameterized queries for Sanity GROQ calls (e.g., `*[_type == "page" && _id == $id]`) and pass an options object with the parameters (`{ id }`). Always guard against falsy parameters (e.g., `if (!id) return [];`) and wrap `client.fetch` in a `try/catch` to gracefully return fallback values like `[]` or `null` to ensure CI builds don't fail unexpectedly.
