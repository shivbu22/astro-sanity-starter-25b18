## 2024-03-20 - [GROQ Injection in Sanity Query]
**Vulnerability:** GROQ query injection vulnerability in `src/data/page.js` where user-controlled string interpolation was used to insert IDs into Sanity fetch queries instead of query parameters.
**Learning:** Even internal ID parameters require parameterization. Using template literals for variable interpolation within GROQ queries creates a potential vector for data exposure or injection attacks if that variable could ever be manipulated. Furthermore, when using parameterized Sanity GROQ queries in Astro pages where `id` might be evaluated as `undefined`, Sanity will throw errors during static site generation if a falsy check is not implemented.
**Prevention:** Always use Sanity's `$param` parameterized query syntax and pass variables as a separate context object (`{ param }`) to `client.fetch()`, never string concatenation. Ensure falsy/undefined parameter values are handled via an early return (like `if (!id) return [];`) before calling `client.fetch()`.
