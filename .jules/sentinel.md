## 2026-08-07 - [GROQ Query Injection via String Interpolation]
**Vulnerability:** Found GROQ query injection vulnerability where user-supplied input (`id`) was being directly interpolated into a GROQ query via string literals in `src/data/page.js` (`_id == "${id}"`).
**Learning:** Sanity GROQ queries act as a powerful query language, and string interpolation creates injection vulnerabilities similarly to SQL injection. During development, a critical architectural nuance was discovered: Astro static site generation (SSG) or SSR evaluation may pass `undefined` parameters to the fetching function. When a parameterized query is executed with `undefined` parameters, the Sanity client can throw errors and break the build.
**Prevention:** Always use parameterized queries (e.g., `$id`) instead of string interpolation for variables. Additionally, explicitly handle falsy/undefined parameter values (e.g., `if (!id) return [];`) before calling `client.fetch` in data fetching functions to ensure Astro builds succeed during static generation.
