## 2024-03-01 - [CRITICAL] GROQ Query Injection\n**Vulnerability:** The `getPageById` function in `src/data/page.js` used string interpolation (`_id == "${id}"`) to insert the `id` argument directly into a GROQ query. This allows for GROQ query injection if the `id` is ever sourced from untrusted input, potentially allowing an attacker to extract unauthorized data or bypass query constraints.\n**Learning:** This existed because standard template literals are often intuitively used for string building, and developers might not be fully aware that GROQ, like SQL, requires parameterized queries to safely handle dynamic inputs. The query parser executes whatever text is constructed.\n**Prevention:** Always use parameterized queries for dynamic values in GROQ queries. Replace string interpolations (e.g., `${id}`) with variable placeholders (e.g., `$id`) and pass the variables as a separate parameters object to the `client.fetch()` function (e.g., `client.fetch(query, { id })`).
